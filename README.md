# Лабораторная работа: Использование Apache Kafka

**Цель:** знакомство с API для обработки потоковых больших данных, а также создание бизнес-плана для инфраструктуры больших данных.

**Задание, ч.1:** Разработайте приложение, использующее Kafka для решения следующих задач:
- преобразование данных;
- фильтрация данных;
- агрегирование данных.

---

## 1. Структура проекта
├── docker-compose.yaml # Конфигурация сервисов Docker

├── Dockerfile # Сборка образа producer'а

├── requirements.txt # Python-зависимости producer'а

├── producer/

│ └── producer.py # Отправляет CSV-данные в Kafka

├── spark/

│ └── streaming.py # Потоковая обработка в Spark

└── data/

└── movies_metadata.csv # Исходный набор данных (TMDB)


### Описание файлов

- **`data/movies_metadata.csv`** – набор данных о фильмах, загружаемый из [Kaggle MovieLens/TMDB](https://www.kaggle.com/datasets/rounakbanik/the-movies-dataset). Содержит информацию о бюджете, доходах, рейтингах и пр.

- **`producer/producer.py`** – Python-скрипт, использующий библиотеку `kafka-python`. Читает CSV-файл с помощью pandas и построчно отправляет каждую запись в топик Kafka `movies` с задержкой 10 мс (имитация потокового источника).

- **`spark/streaming.py`** – приложение PySpark, которое:
  1. Читает поток из Kafka-топика `movies`.
  2. Приводит поля к нужным типам (преобразование).
  3. Отбрасывает фильмы с неположительным бюджетом/доходом и малым количеством голосов (фильтрация).
  4. Вычисляет скользящее агрегирование за 1-минутные окна: среднюю выручку (`avg_revenue`) и количество фильмов (`movie_count`) – агрегация.
  5. Пишет результат в Kafka-топик `movies_aggregated`.

- **`docker-compose.yaml`** – описывает сервисы:
  - `kafka` (один брокер в режиме KRaft, без ZooKeeper)
  - `spark` (образ `apache/spark:3.5.1`, запускает `spark/streaming.py`)
  - `producer` (сборка через Dockerfile, отправляет данные в Kafka)

- **`Dockerfile`** – задаёт образ для producer'а: python:3.10, установка зависимостей из `requirements.txt`, копирование и запуск `producer.py`.

- **`requirements.txt`** – содержит `kafka-python` и `pandas`.

## 2. Инструкция по запуску

### Предварительные требования
- Установленный [Docker](https://docs.docker.com/get-docker/) и Docker Compose.
- Файл `movies_metadata.csv`, помещённый в папку `data/` (можно скачать по ссылке выше).

### Сборка и запуск

1. Откройте терминал в корневой папке проекта (`lab_6`).

2. Запустите все сервисы одной командой:
   ```bash
   docker-compose up --build

Первый запуск может занять несколько минут: Docker скачает образы, соберёт producer, Spark загрузит коннектор для Kafka.

Сервисы стартуют в правильном порядке: Kafka → Spark → Producer.

3. Дождитесь завершения работы producer'а. В логах появится:
   producer-1 | Data sent to Kafka
После этого producer остановится (статус `Exited (0)`). Spark продолжит работу в ожидании новых данных.

4. Для просмотра результатов агрегации выполните в другом терминале:
```bash
docker-compose exec kafka kafka-console-consumer \
  --bootstrap-server localhost:9092 \
  --topic movies_aggregated \
  --from-beginning
```
Вы увидите непрерывный поток JSON-объектов с агрегированными данными.

## 3. Результаты работы

После запуска и полной отправки CSV-файла (около 45 000 записей) в топике `movies_aggregated` появляются записи вида:

```json
{"window":{"start":"2026-05-01T01:49:00.000Z","end":"2026-05-01T01:50:00.000Z"},"avg_revenue":1.07962839E7,"movie_count":10}
{"window":{"start":"2026-05-01T01:49:00.000Z","end":"2026-05-01T01:50:00.000Z"},"avg_revenue":2.069764888235294E7,"movie_count":17}
{"window":{"start":"2026-05-01T01:50:00.000Z","end":"2026-05-01T01:51:00.000Z"},"avg_revenue":9.553108E7,"movie_count":21}
...
```

### Интерпретация:
- Каждая строка – это состояние агрегации по минутному окну (временная метка окна в start/end).
- avg_revenue – средняя выручка фильмов, удовлетворяющих фильтру (budget > 0, revenue > 0, vote_count > 10), в данном окне.
- movie_count – количество таких фильмов в окне.

**Часть 2. Бизнес-план внедрения инфраструктуры больших данных**

## 1. Резюме

На основе прототипа из Части 1 (Kafka + Spark Streaming для фильмов) предлагается внедрение потоковой платформы для видеосервиса **StreamFlix**. Цель — аналитика и персонализация в реальном времени. Срок: 6 месяцев, бюджет: ~375 000 USD.

## 2. Текущие проблемы
- Пакетная ETL (ночные отчёты, задержка до суток).
- Рекомендации обновляются редко, не учитывают текущую сессию.
- Дорогая поддержка разрозненных систем.

## 3. Цели
- Единая потоковая архитектура, метрики с задержкой ≤ 1 мин.
- Повышение точности рекомендаций на 15–20 %.
- Снижение TCO на 20 %.

## 4. Дорожная карта
- **Месяцы 1–2 (пилот):** кластер Kafka (3 брокера) + Spark, один сценарий «популярность контента в реальном времени».
- **Месяцы 3–4 (миграция):** перевод 80 % отчётов на стриминг, online-фичи для рекомендаций.
- **Месяцы 5–6 (промышленная эксплуатация):** отключение legacy, обучение, A/B-тесты.

## 5. Бюджет (ключевые статьи)
- Оборудование/облако: 120 000 рублей.
- Лицензии (Confluent/Databricks) или поддержка open-source: 80 000 рублей/год.
- Разработка (3 инженера, 6 мес.): 120 000 рублей.
- Обучение и резерв: 55 000 рублей.

## 6. Ожидаемые выгоды
- Время отчётов: с часов до секунд.
- Рост вовлечённости и выручки за счёт актуальных рекомендаций.
- Уменьшение затрат на инфраструктуру на 20–25 %.

## 7. Риски
- Нехватка компетенций → пилот и обучение.
- Сложность интеграции с legacy → поэтапный переход, коннекторы Kafka.
- Зависимость от вендора → приоритет open-source API.

## 8. Заключение
Прототип потоковой обработки из Части 1 прямо масштабируется до корпоративной платформы, позволяя получать бизнес-ценность из данных в реальном времени с быстрой окупаемостью.
